# PostgreSQL Flexible Server Module

## Summary

The Azure PostgreSQL Flexible Server module is a Terraform module that provides an easy and consistent way to create and manage PostgreSQL flexible servers in Azure. This module enforces organization-specific naming conventions and security policies while simplifying the provisioning process. A private endpoint is always provisioned (subresource `postgresqlServer`); callers supply the subnet and DNS zone via `private_endpoint_settings`.

## How to use it?

The module always provisions a private endpoint for the server (`postgresqlServer` subresource). Every caller must supply `private_endpoint_settings` with the subnet ID where the PEP NIC lands and the resource ID of the `privatelink.postgres.database.azure.com` DNS zone. `public_network_access_enabled` defaults to `false` (PEP-only posture). This module does not manage firewall rules, so enabling public access alone does not make the server reachable from the internet.

### Networking mode

The server is created in the *public access* networking mode and reached through the private endpoint. VNet integration (a delegated subnet) is a different mode and cannot be combined with private endpoints, so `delegated_subnet_id` and `private_dns_zone_id` are intentionally not exposed.

### Administrator account

The local administrator login is set through `admin_settings.local_username`. Its password is generated by the module at creation, is never output, and Terraform ignores any later change to it. Reset it out-of-band when the account is needed, for example:

```shell
az postgres flexible-server update --resource-group <rg> --name <server> --admin-password '<new password>'
```

The login cannot be changed after creation without forcing a new server.

### What is only applied at creation

Scaling and upgrades are operational tasks, so Terraform sets these values when the server is created and ignores later changes to them (and to the live values): `sku_name`, `storage_mb`, `storage_tier`, `postgresql_version`, `zone` and `high_availability.standby_availability_zone`. Changing them in the module inputs afterwards does nothing; scale or upgrade the server through the Azure Portal or CLI instead. `postgresql_version` in particular would otherwise force a new server, because the provider treats a version change as a replacement.

### Other notes

- `sequence_number` is optional and intended only for power-user scenarios where multiple servers share the same workload/env/region. Omit it for the common single-instance case. When supplied, it is appended to the resource name as a zero-padded `-NNN` suffix.
- Server names are globally unique, because they become the `<name>.postgres.database.azure.com` host name.
- The maintenance window is fixed to Saturday 23:00 UTC.
- `postgresql_version` accepts 13 to 16. The `azurerm` 3.x provider does not know newer major versions.
- Not supported by this module: Microsoft Entra authentication, customer-managed keys, identities, and restore or replica creation (`create_mode` is always `Default`).

### Burstable Server (Minimal Configuration)

This example shows the minimum required configuration, suitable for a development environment.

```hcl
module "postgresql_flexible_server" {
  source = "git::github.com/Nmbrs/tf-modules//azure/postgresql_flexible_server"

  workload            = "billing"
  company_prefix      = "nmbrs"
  environment         = "dev"
  location            = "westeurope"
  resource_group_name = "rg-billing-dev"

  admin_settings = {
    local_username = "pgcloudadmin"
  }

  postgresql_version = "16"
  sku_name           = "B_Standard_B1ms"

  private_endpoint_settings = {
    subnet_id = "/subscriptions/.../subnets/snet-private-endpoints"
    private_dns_zone_ids = {
      postgresqlServer = module.dns_zone_postgresql.id
    }
  }
}
```

### Zone-Redundant High Availability Server

This example shows a General Purpose server with zone-redundant high availability, larger storage and auto-grow.

```hcl
module "postgresql_flexible_server" {
  source = "git::github.com/Nmbrs/tf-modules//azure/postgresql_flexible_server"

  workload            = "billing"
  company_prefix      = "nmbrs"
  environment         = "prod"
  location            = "westeurope"
  resource_group_name = "rg-billing-prod"

  admin_settings = {
    local_username = "pgcloudadmin"
  }

  postgresql_version = "16"
  sku_name           = "GP_Standard_D4ds_v5"
  storage_mb         = 131072
  auto_grow_enabled  = true

  zone = "1"
  high_availability = {
    mode                      = "ZoneRedundant"
    standby_availability_zone = "2"
  }

  backup_retention_days        = 35
  geo_redundant_backup_enabled = true

  private_endpoint_settings = {
    subnet_id = "/subscriptions/.../subnets/snet-private-endpoints"
    private_dns_zone_ids = {
      postgresqlServer = module.dns_zone_postgresql.id
    }
  }
}
```

### Custom Named Server

This example shows how to override the standard naming convention. `workload` and `company_prefix` are required inputs, so set them to `null` when `override_name` is used.

```hcl
module "postgresql_flexible_server" {
  source = "git::github.com/Nmbrs/tf-modules//azure/postgresql_flexible_server"

  override_name       = "psql-legacy-system"
  workload            = null
  company_prefix      = null
  environment         = "prod"
  location            = "westeurope"
  resource_group_name = "rg-legacy-prod"

  admin_settings = {
    local_username = "pgcloudadmin"
  }

  postgresql_version = "15"
  sku_name           = "GP_Standard_D2ds_v5"

  private_endpoint_settings = {
    subnet_id = "/subscriptions/.../subnets/snet-private-endpoints"
    private_dns_zone_ids = {
      postgresqlServer = module.dns_zone_postgresql.id
    }
  }
}
```
