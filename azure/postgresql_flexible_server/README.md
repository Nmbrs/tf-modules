# PostgreSQL Flexible Server Module

## Summary

The Azure PostgreSQL Flexible Server module is a Terraform module that provides an easy and consistent way to create and manage Azure Database for PostgreSQL Flexible Server instances. This module enforces organization-specific naming conventions and security policies while simplifying the provisioning process. It manages the server, its private endpoint (subresource `postgresqlServer`; callers supply the subnet and DNS zone via `private_endpoint_settings`) and its Entra ID administrator group. Databases, roles and grants are not managed here: they are created outside Terraform by the application team (migrations, `psql`), the same way schema lives outside Terraform for the SQL servers.

## How to use it?

The module always provisions a private endpoint for the server (`postgresqlServer` subresource). Every caller must supply `private_endpoint_settings` with the subnet ID where the PEP NIC lands and the resource ID of the `privatelink.postgres.database.azure.com` DNS zone. `public_network_access_enabled` defaults to `false` (PEP-only posture); set it to `true` only when public reachability is genuinely needed alongside the private endpoint. The module does not use VNet integration (`delegated_subnet_id`).

`admin_settings.azuread_group_name` is set as the Entra ID administrator of the server. With `azuread_authentication_only_enabled = true` (the default) no local administrator and no password exist anywhere; workloads authenticate with managed-identity tokens. With `false`, the module also creates the local administrator `local_username` with a strong generated password that is never output: reset it out-of-band (`az postgres flexible-server update --admin-password`) when the account is needed, Terraform ignores later changes to it. Choose the mode before the first apply: Azure only accepts the local administrator login at creation, so switching an existing server from Entra-only to password authentication replaces it.

Databases, roles and grants are created outside Terraform by the application team after the server exists; the module has no `databases` input on purpose.

`sequence_number` is optional and intended only for scenarios where multiple servers share the same workload/env/region. Omit it for the common single-instance case. When supplied, it is appended to the resource name as a zero-padded `-NNN` suffix.

### Minimal development server (Entra-only authentication)

This example shows the minimum required configuration: a Burstable server with 32 GB of storage, PostgreSQL 16, 7 days of locally redundant backups and no local administrator.

```hcl
module "postgresql_server" {
  source = "git::github.com/Nmbrs/tf-modules//azure/postgresql_flexible_server"

  workload            = "pagentui"
  company_prefix      = "nmbrs"
  environment         = "dev"
  location            = "westeurope"
  resource_group_name = "rg-payrollagentui-dev"

  sku_name = "B_Standard_B1ms"

  admin_settings = {
    azuread_group_name = "sg-sql-admins-dev"
    local_username     = "psqlcloudadmin"
  }

  private_endpoint_settings = {
    subnet_id = "/subscriptions/.../subnets/snet-private-endpoints"
    private_dns_zone_ids = {
      postgresqlServer = module.dns_zone_postgresql.id
    }
  }
}
```

### Server with password authentication enabled

This example keeps the Entra ID administrator and additionally enables the local administrator `psqlcloudadmin` for client libraries that cannot use Entra ID tokens. The generated password is never output.

```hcl
module "postgresql_server" {
  source = "git::github.com/Nmbrs/tf-modules//azure/postgresql_flexible_server"

  workload            = "reporting"
  company_prefix      = "nmbrs"
  environment         = "test"
  location            = "westeurope"
  resource_group_name = "rg-reporting-test"

  sku_name           = "GP_Standard_D2s_v3"

  postgresql_version = "15"

  admin_settings = {
    azuread_group_name                  = "sg-sql-admins-test"

  private_endpoint_settings = {
    subnet_id = "/subscriptions/.../subnets/snet-private-endpoints"
    private_dns_zone_ids = {
      postgresqlServer = module.dns_zone_postgresql.id
    }
  }
}
```

### Zone-redundant production server

This example shows a General Purpose server with a zone-redundant standby, 35 days of geo-redundant backups and a pinned primary zone. High availability is not available on Burstable SKUs, and geo-redundancy can only be chosen at creation.

```hcl
module "postgresql_server" {
  source = "git::github.com/Nmbrs/tf-modules//azure/postgresql_flexible_server"

  workload            = "payroll"
  company_prefix      = "nmbrs"
  environment         = "prod"
  location            = "westeurope"
  resource_group_name = "rg-payroll-prod"

  sku_name               = "GP_Standard_D4s_v3"
  storage_mb             = 262144
  zone                   = "1"
  high_availability_mode = "ZoneRedundant"

  backup_settings = {
    retention_days        = 35
    geo_redundant_enabled = true
  }

  admin_settings = {
    azuread_group_name = "sg-sql-admins-prod"
    local_username     = "psqlcloudadmin"
  }

  private_endpoint_settings = {
    subnet_id = "/subscriptions/.../subnets/snet-private-endpoints"
    private_dns_zone_ids = {
      postgresqlServer = module.dns_zone_postgresql.id
    }
  }
}
```

### Custom named server

This example shows how to override the standard naming convention. The name is lowercased and must be a valid, globally unique DNS label (3 to 63 characters, lowercase letters, digits and hyphens).

```hcl
module "postgresql_server" {
  source = "git::github.com/Nmbrs/tf-modules//azure/postgresql_flexible_server"

  override_name       = "psql-legacy-system"
  environment         = "prod"
  location            = "westeurope"
  resource_group_name = "rg-legacy-prod"

  sku_name = "MO_Standard_E2s_v3"

  admin_settings = {
    azuread_group_name = "sg-sql-admins-prod"
    local_username     = "psqlcloudadmin"
  }

  private_endpoint_settings = {
    subnet_id = "/subscriptions/.../subnets/snet-private-endpoints"
    private_dns_zone_ids = {
      postgresqlServer = module.dns_zone_postgresql.id
    }
  }
}
```

## Decisions

Design decisions taken for the first version of this module (tf-automation #342, tf-modules #433):

1. **Connectivity: private endpoint, not VNet integration.** The server is reached through a private endpoint in the shared private-endpoints subnet, exactly like the redis, SQL and Service Bus modules. The module never sets `delegated_subnet_id` or `private_dns_zone_id` on the server. One connectivity model per module; VNet integration (delegated subnets) is out of scope.
2. **Entra ID administrator group.** The module only takes a group display name (`admin_settings.azuread_group_name`) and resolves it with `data.azuread_group`. Callers reuse the existing `sg-sql-admins-{environment}` groups; no dedicated `sg-psql-admins-*` groups are created.
3. **Entra-only authentication by default.** `azuread_authentication_only_enabled` defaults to `true`, so no local password exists anywhere and no `random_password` is created. Password authentication is an explicit opt-in per server, with the same generated-once, never-output, ignored-afterwards handling as the SQL Server module.
4. **Environment defaults belong to the caller.** `backup_settings` defaults to 7 days of locally redundant backups; audited environments (prod, sand, stage) pass 35 days and `geo_redundant_enabled = true`. Geo-redundancy must be right at creation because changing it replaces the server. High availability is off unless `high_availability_mode` is set, and is rejected on Burstable SKUs.
5. **Scaling stays Terraform-managed.** `sku_name` and `storage_mb` are not in `ignore_changes` (like the redis `cache_size_in_gb`), while `auto_grow_enabled` is always on. Storage can only grow; a SKU change restarts the server. `zone` and the standby zone are ignored after creation because Azure swaps them on failover. Tags are ignored and there is no `tags` input, as in every other data-tier module.
