# PostgreSQL Flexible Server Module

## Summary

The Azure PostgreSQL Flexible Server module is a Terraform module that provides an easy and consistent way to create and manage PostgreSQL flexible servers in Azure. This module enforces organization-specific naming conventions and security policies while simplifying the provisioning process. A private endpoint is always provisioned (subresource `postgresqlServer`) and a Microsoft Entra group is always set as the server administrator; callers supply the subnet and DNS zone via `private_endpoint_settings` and the group via `admin_settings`.

## How to use it?

### Networking

The module always provisions a private endpoint for the server (`postgresqlServer` subresource). Every caller must supply `private_endpoint_settings` with the subnet ID where the PEP NIC lands and the resource ID of the `privatelink.postgres.database.azure.com` DNS zone. `public_network_access_enabled` defaults to `false` (PEP-only posture). This module does not manage firewall rules, so enabling public access alone does not make the server reachable from the internet.

The server is created in the *public access* networking mode and reached through the private endpoint. VNet integration (a delegated subnet) is a different mode and cannot be combined with private endpoints, so `delegated_subnet_id` and `private_dns_zone_id` are intentionally not exposed.

### Authentication and administrator

`admin_settings.azuread_group_name` is the display name of a Microsoft Entra security group, which is set as the administrator of the server. The identity running Terraform needs permission to read the group.

- With `azuread_authentication_only_enabled = true` (the default), Entra ID is the only authentication method. No local administrator and no password exist.
- With `azuread_authentication_only_enabled = false`, the server is created in hybrid mode: Entra ID plus the local administrator `local_username` (required in this mode). Its password is generated by the module at creation, is never output, and Terraform ignores any later change to it. Reset it out-of-band when the account is needed, for example:

```shell
az postgres flexible-server update --resource-group <rg> --name <server> --admin-password '<new password>'
```

Choose the mode when the server is created. A hybrid server can later be locked down by setting the flag to `true`, but switching back to password authentication is not supported through Terraform.

### What is only applied at creation

Scaling and upgrades are operational tasks, so Terraform sets these values when the server is created and ignores later changes to them (and to the live values): `postgresql_version`, `sku_name`, `storage_mb`, `auto_grow_enabled`, `zone` and the standby zone. Changing them in the module inputs afterwards does nothing; scale or upgrade the server through the Azure Portal or CLI instead. `postgresql_version` in particular would otherwise force a new server, because the provider treats a version change as a replacement. Major version upgrades are done in place by Azure; run its upgrade validation checks first.

### High availability and backups

High availability is off by default. Set `high_availability_mode` to `SameZone` or `ZoneRedundant` to enable it; it is not supported on Burstable (`B_`) SKUs, and Azure chooses the standby zone.

Backups are kept for 7 days by default (`backup_settings.retention_days`, 7 to 35). Geo-redundant backup (`backup_settings.geo_redundant_enabled`) is only available in Azure paired regions and can only be chosen at creation: changing it afterwards replaces the server.

### Naming

- `sequence_number` is optional and intended only for scenarios where multiple servers share the same workload/env/region. Omit it for the common single-instance case. When supplied, it is appended to the resource name as a zero-padded `-NNN` suffix.
- Server names are globally unique, because they become the `<name>.postgres.database.azure.com` host name.
- The name can have at most 59 characters, because the private endpoint is named `pep-<name>-postgresqlserver` and Azure limits that to 80 characters. The module fails at plan with a message naming the server when it is too long.

### Other notes

- The maintenance window is fixed to Saturday 23:00 UTC.
- `postgresql_version` accepts 13 to 16. The `azurerm` 3.x provider does not know newer major versions.
- Not supported by this module: customer-managed keys, identities on the server, restore or replica creation (`create_mode` is always `Default`), firewall rules and VNet integration.

### Minimal development server (Entra-only authentication)

This example shows the minimum required configuration: a Burstable server with 32 GB of storage and PostgreSQL 16, with no local administrator.

```hcl
module "postgresql_flexible_server" {
  source = "git::github.com/Nmbrs/tf-modules//azure/postgresql_flexible_server"

  workload            = "billing"
  company_prefix      = "nmbrs"
  environment         = "dev"
  location            = "westeurope"
  resource_group_name = "rg-billing-dev"

  sku_name = "B_Standard_B1ms"

  admin_settings = {
    azuread_group_name = "sg-postgresql-admins"
  }

  private_endpoint_settings = {
    subnet_id = "/subscriptions/.../subnets/snet-private-endpoints"
    private_dns_zone_ids = {
      postgresqlServer = module.dns_zone_postgresql.id
    }
  }
}
```

### Server with a local administrator (hybrid)

This example keeps the Entra administrator group and additionally creates the local administrator `pgcloudadmin`, for tools that cannot use Entra ID tokens. The generated password is never output.

```hcl
module "postgresql_flexible_server" {
  source = "git::github.com/Nmbrs/tf-modules//azure/postgresql_flexible_server"

  workload            = "reporting"
  company_prefix      = "nmbrs"
  environment         = "test"
  location            = "westeurope"
  resource_group_name = "rg-reporting-test"

  sku_name           = "GP_Standard_D2ds_v5"
  storage_mb         = 131072
  postgresql_version = "15"

  admin_settings = {
    azuread_group_name                  = "sg-postgresql-admins"
    azuread_authentication_only_enabled = false
    local_username                      = "pgcloudadmin"
  }

  private_endpoint_settings = {
    subnet_id = "/subscriptions/.../subnets/snet-private-endpoints"
    private_dns_zone_ids = {
      postgresqlServer = module.dns_zone_postgresql.id
    }
  }
}
```

### Zone-redundant production server

This example shows a General Purpose server with zone-redundant high availability, a pinned primary zone and 35 days of geo-redundant backups.

```hcl
module "postgresql_flexible_server" {
  source = "git::github.com/Nmbrs/tf-modules//azure/postgresql_flexible_server"

  workload            = "billing"
  company_prefix      = "nmbrs"
  environment         = "prod"
  location            = "westeurope"
  resource_group_name = "rg-billing-prod"

  sku_name               = "GP_Standard_D4ds_v5"
  storage_mb             = 262144
  zone                   = "1"
  high_availability_mode = "ZoneRedundant"

  backup_settings = {
    retention_days        = 35
    geo_redundant_enabled = true
  }

  admin_settings = {
    azuread_group_name = "sg-postgresql-admins"
  }

  private_endpoint_settings = {
    subnet_id = "/subscriptions/.../subnets/snet-private-endpoints"
    private_dns_zone_ids = {
      postgresqlServer = module.dns_zone_postgresql.id
    }
  }
}
```

### Custom named server

This example shows how to override the standard naming convention. `workload` and `company_prefix` are required inputs, so set them to `null` when `override_name` is used.

```hcl
module "postgresql_flexible_server" {
  source = "git::github.com/Nmbrs/tf-modules//azure/postgresql_flexible_server"

  override_name       = "pgsql-legacy-system"
  workload            = null
  company_prefix      = null
  environment         = "prod"
  location            = "westeurope"
  resource_group_name = "rg-legacy-prod"

  sku_name = "GP_Standard_D2ds_v5"

  admin_settings = {
    azuread_group_name = "sg-postgresql-admins"
  }

  private_endpoint_settings = {
    subnet_id = "/subscriptions/.../subnets/snet-private-endpoints"
    private_dns_zone_ids = {
      postgresqlServer = module.dns_zone_postgresql.id
    }
  }
}
```
